# 구성 골격 카탈로그

`shape_plan`을 빈 캔버스에서 시작하지 않는다. 아래 골격 중 블록 관계에 맞는 것을 고르고, 슬롯 좌표를 출발점으로 삼아 내용에 맞게 조정한다. 골격은 배치의 하한선이지 정답이 아니다. 슬롯 안에서 칩·노드·연결선·강조 막대를 자유롭게 더한다.

모든 골격은 렌더러의 배치 품질 게이트를 통과하도록 잡았다. 게이트는 다음을 검사한다.

| 검사 | 기준 | 왜 필요한가 |
| --- | --- | --- |
| 표면 점유율 | 사각형·타원·마름모가 본문 안전영역의 60% 이상(가로형 55%) | 상자 몇 개를 띄엄띄엄 놓고 아래를 비우는 장표를 막는다 |
| 빈 가로 띠 | 표면 도형이 하나도 없는 가로 띠가 120px 이하(가로형 80px) | 하단 30~40%가 비는 장표를 막는다 |
| 좌우 배치 | 블록 4개 이상이면 좌우로 나란한 블록 쌍이 1개 이상 | 1열 세로 스택을 막는다 |
| 텍스트 위계 | 블록마다 굵은 14pt 이상 헤드라인과 더 작은 본문이 별도 텍스트 도형 | 헤드라인과 설명을 한 상자에 같은 크기로 넣는 것을 막는다 |
| 텍스트 넘침 | 맑은 고딕 실측 폭(한글 1.0em, 영문 0.5em)으로 줄 수를 계산해 상자 안에 들어가야 함 | 미리보기 PNG는 대체 글꼴로 한글이 25% 좁게 보여 PowerPoint에서 넘치는 문장을 숨긴다 |
| 곡선 도형 안 텍스트 | 타원·마름모 안 텍스트는 내접 사각형(타원 71%, 마름모 50%) 안에 들어가야 함 | 타원에 문단을 욱여넣고 마름모에 두 줄 문장을 쓰는 것을 막는다 |

## 글자 크기와 상자 크기 어림

맑은 고딕 기준 한 글자 폭은 글자 크기(pt)의 약 1.33px다. 한 줄 높이는 약 1.3em이다.

| 용도 | 크기 | 굵기 | 한 줄에 들어가는 한글 글자 수 (상자 폭 300px 기준) |
| --- | ---: | --- | ---: |
| 블록 헤드라인 | 16~18pt | 굵게 | 12~13자 |
| 본문 문장 | 12~13pt | 보통 | 16~17자 |
| 칩·노드 라벨 | 11~12pt | 굵게 | 18~19자 |
| 결론 밴드 헤드라인 | 17~18pt | 굵게 | 12~13자 |

본문 한 줄 높이는 13pt에서 약 22px다. 세 줄 문장이면 상자 높이를 80px 이상으로 잡는다. 60자 안팎의 문장은 폭 280px 상자에서 네 줄, 폭 600px 상자에서 두 줄이다.

## 세로형 골격 (720×1280, 본문 24~696 × 166~1230)

### A. 상단 2단 · 중앙 허브 · 하단 2단 · 결론 밴드

블록 관계: 입력 두 갈래가 핵심 처리로 모이고, 처리 결과가 두 갈래로 나뉜 뒤 통제·효과로 마무리될 때. 블록 6개.

```text
┌──────────────┐ ┌──────────────┐   36,180  312×230  |  372,180  312×230
│  블록 1      │ │  블록 2      │
└──────┬───────┘ └───────┬──────┘
       └──────┬──────────┘
        ┌─────┴──────┐                216,460  288×220  (타원 또는 둥근 사각형)
        │   허브 3   │
        └─────┬──────┘
       ┌──────┴──────────┐
┌──────┴───────┐ ┌───────┴──────┐   36,720  312×220  |  372,720  312×220
│  블록 4      │ │  블록 5      │
└──────────────┘ └──────────────┘
┌───────────────────────────────┐   36,970  648×250
│  결론·통제 밴드 6 (칩 3개)    │
└───────────────────────────────┘
```

허브가 타원이면 텍스트는 내접 사각형(약 204×156) 안에 둔다. 헤드라인 17pt 한 줄은 13자 이하로 쓰고 본문은 13pt 네 줄 이내로 줄인다. 허브 좌우 여백(36~216, 504~684)에 입력 칩(150×44)을 두고 허브로 연결하면 빈 띠가 생기지 않는다.

### B. 좌측 단계 레일 · 우측 상세 패널 · 하단 통제 밴드

블록 관계: 순차 단계 4~5개가 있고 각 단계의 세부와 통제가 따로 있을 때. 블록 5~6개.

```text
┌────────┐ ┌────────────────────────┐   레일 36,180 200×760  |  패널 1  256,180 428×240
│ 단계 1 │ │  패널 1                │
│   │    │ ├────────────────────────┤   패널 2  256,440 428×240
│ 단계 2 │ │  패널 2                │
│   │    │ ├────────────────────────┤   패널 3  256,700 428×240
│ 단계 3 │ │  패널 3                │
│   │    │ └────────────────────────┘
│ 단계 4 │
└────────┘
┌───────────────────────────────────┐   36,960  648×260
│  통제·품질 밴드 (칩 3~4개)        │
└───────────────────────────────────┘
```

레일 안의 단계는 40px 원 번호 + 라벨(12pt 굵게)로 만들고 원을 연결선으로 잇는다. 레일 자체가 한 블록이고 패널 세 개와 밴드가 나머지 블록이다.

### C. 풀폭 범위 밴드 · 중앙 3열 파이프라인 · 하단 2단

블록 관계: 대상·범위가 먼저 정의되고, 처리 단계가 병렬 3열로 흐른 뒤, 결과와 통제가 나뉠 때. 블록 6개.

```text
┌───────────────────────────────────┐   36,180  648×150   범위·규모 밴드 (수치 강조)
└───────────────────────────────────┘
┌─────────┐ ┌─────────┐ ┌─────────┐   36,350 204×340 | 258,350 204×340 | 480,350 204×340
│ 열 1    │→│ 열 2    │→│ 열 3    │   (각 열: 헤드라인 + 본문 + 노드 2~3개 세로 배치)
└─────────┘ └─────────┘ └─────────┘
┌──────────────┐ ┌──────────────┐   36,710  312×240  |  372,710  312×240
│  결과 블록   │ │  통제 블록   │
└──────────────┘ └──────────────┘
┌───────────────────────────────────┐   36,970  648×250
│  적용 결론 밴드                   │
└───────────────────────────────────┘
```

열 폭 204px에서는 본문 12pt가 한 줄에 13자다. 열 안 문장은 두 줄 이내로 쓰고 나머지는 하단 블록으로 옮긴다.

### D. 세로 스윔레인 3레인 · 하단 결과

블록 관계: 역할·주체가 셋(사용자, 시스템, 관리자 등)이고 각 역할의 처리가 위에서 아래로 진행될 때. 블록 5개.

```text
┌─────────┐ ┌─────────┐ ┌─────────┐   36,180 204×720 | 258,180 204×720 | 480,180 204×720
│ 레인 1  │ │ 레인 2  │ │ 레인 3  │   (레인 머리 40px + 노드 3~4개 세로 + 레인 간 연결선)
│  ○      │ │  ○      │ │  ○      │
│  ○      │ │  ○      │ │  ○      │
│  ○      │ │  ○      │ │  ○      │
└─────────┘ └─────────┘ └─────────┘
┌──────────────┐ ┌──────────────┐   36,930  312×290  |  372,930  312×290
│  결과 블록   │ │  통제 블록   │
└──────────────┘ └──────────────┘
```

### E. 계층형 (상단 1 · 중단 3 · 하단 2)

블록 관계: 목표 하나가 구현 요소 셋으로 나뉘고, 요소들이 두 가지 효과·통제로 귀결될 때. 블록 6개.

```text
┌───────────────────────────────────┐   36,180  648×170   목표·정의 블록
└────────────────┬──────────────────┘
      ┌──────────┼──────────┐
┌─────┴───┐ ┌────┴────┐ ┌───┴─────┐   36,400 204×330 | 258,400 204×330 | 480,400 204×330
│ 요소 1  │ │ 요소 2  │ │ 요소 3  │
└─────┬───┘ └────┬────┘ └───┬─────┘
      └──────┬───┴─────┬────┘
┌────────────┴───┐ ┌───┴────────────┐   36,770  312×450  |  372,770  312×450
│  효과 블록     │ │  통제 블록     │
└────────────────┘ └────────────────┘
```

### F. 매핑형 (좌 항목 4 ↔ 우 대응 4 · 하단 결론)

블록 관계: 요구 항목 여러 개가 각각의 구현 방식과 1:1 또는 1:N으로 대응할 때. 블록 5~6개.

```text
┌──────────────┐     ┌──────────────┐   좌 36,180 280×170 ×4 (간격 20)
│ 항목 1       │────▶│ 대응 1       │   우 404,180 280×170 ×4
├──────────────┤     ├──────────────┤   가운데 316~404 는 연결선 전용
│ 항목 2       │────▶│ 대응 2       │
├──────────────┤     ├──────────────┤
│ 항목 3       │────▶│ 대응 3       │
├──────────────┤     ├──────────────┤
│ 항목 4       │────▶│ 대응 4       │
└──────────────┘     └──────────────┘
┌───────────────────────────────────┐   36,960  648×260
│  결론 밴드                        │
└───────────────────────────────────┘
```

좌우 각 열이 한 블록이 될 수도 있고(항목 열 = 블록 1, 대응 열 = 블록 2), 행 하나가 한 블록이 될 수도 있다. 블록 수와 관계에 맞춰 정한다.

## `composition`으로 적기

좌표를 직접 쓰지 않는다. 청사진에 `composition`을 적고 `tools/slide-renderer/bin/compose-shape-plan.mjs --project <dir> --write`를 실행하면 렌더러가 `shape_plan`을 만든다. 골격과 슬롯 이름은 `--skeletons`로 출력할 수 있다.

```json
{
  "composition": {
    "skeleton": "C-deep",
    "rationale": "범위 밴드에서 3열 파이프라인으로 흐르고 저장 결과가 하단 두 블록으로 내려간다.",
    "signature": "portrait-scope-band-three-column-pipeline-v1",
    "blocks": {
      "scope":     { "slot": "band",  "style": "navy", "items": [{ "type": "metric", "value": "4.7TB", "label": "전처리 대상 규모" }] },
      "filter":    { "slot": "col-1", "style": "pale", "accent": "stripe", "items": [{ "type": "chips", "labels": ["중복 문서 제거", "최고보안등급 제외"] }] },
      "refresh":   { "slot": "foot-left", "items": [
        { "type": "loop", "labels": ["신규 문서
수집", "증분
전처리", "색인
반영"], "caption": "모델 교체 시 재임베딩만 수행", "gap": 40 },
        { "type": "note", "pin": "bottom", "label": "일정 연계", "body": "범위 확정 M1~2" }
      ] }
    },
    "connectors": [
      { "from": "filter", "to": "transform", "from_side": "right", "to_side": "left" },
      { "from": "flow-step-1-2", "to": "missing", "from_side": "right", "to_side": "left", "stroke": "accent", "width": 1 }
    ]
  }
}
```

골격 이름과 슬롯:

| 방향 | 골격 | 슬롯 |
| --- | --- | --- |
| 세로 | `A` | `top-left`, `top-right`, `hub`(타원), `foot-left`, `foot-right`, `band` |
| 세로 | `B` | `rail`, `panel-1`, `panel-2`, `panel-3`, `band` |
| 세로 | `B-tall` | `rail`(전체 높이), `panel-1`, `panel-2-left`, `panel-2-right`, `panel-3`, `panel-4` |
| 세로 | `C` | `band`, `col-1`, `col-2`, `col-3`, `foot-left`, `foot-right`, `conclusion` |
| 세로 | `C-deep` | `band`, `col-1`, `col-2`, `col-3`, `foot-left`, `foot-right`(하단이 깊음) |
| 세로 | `D` | `lane-1`, `lane-2`, `lane-3`, `foot-left`, `foot-right` |
| 세로 | `E` | `top`, `mid-1`, `mid-2`, `mid-3`, `foot-left`, `foot-right` |
| 세로 | `F` | `left-1`~`left-4`, `right-1`~`right-4`, `band` |
| 가로 | `G` | `summary`, `flow`, `detail-left`, `detail-right`, `control` |
| 가로 | `H` | `col-1`, `col-2`, `col-3`, `band` |

블록 항목:

- `slot`: 슬롯 이름 또는 `{ left, top, width, height, ellipse? }` 직접 지정. 한 슬롯은 한 블록만 쓴다. 모든 슬롯을 채울 필요는 없지만 비우면 점유율·빈 띠 게이트에 걸릴 수 있다.
- `style`: `white`, `pale`, `navy`, `primary`. 타원 슬롯은 기본 `primary`.
- `accent`: `bar`(좌측 세로 막대) 또는 `stripe`(헤드라인 위 짧은 줄).
- `headline_size`, `body_size`, `align`, `padding`, `item_gap`: 필요할 때만.
- `items[]`: 헤드라인·본문 아래에 순서대로 쌓인다. `pin: "bottom"`이면 슬롯 바닥에 붙는다. `gap`으로 앞 요소와의 간격을 바꾼다.

요소 종류:

| type | 필드 | 그리는 것 |
| --- | --- | --- |
| `chips` | `labels[]`, `layout: "stack"\|"row"`, `fill: white\|accent\|primary\|navy`, `alternate`, `size` | 둥근 사각형 라벨. 세로 쌓기 또는 가로 나열 |
| `loop` | `labels[]`, `caption`, `emphasize_last` | 원 노드를 화살표로 이은 순환·순서, 아래 설명 띠 |
| `checklist` | `labels[]`, `emphasize_last` | 체크 표시가 있는 행 |
| `gauges` | `rows[[label, desc]]` | 왼쪽 막대가 있는 지표 행 |
| `decision` | `input`, `gate`, `outcomes[]` | 입력 칩 → 마름모 → 결과 칩 분기 |
| `steps` | `labels[]`, `spacing` | 번호 원을 세로로 잇는 단계 레일. 남은 높이에 맞춰 퍼진다 |
| `metric` | `value`, `label` | 슬롯 우측 상단 수치 배지. 본문 폭을 그만큼 줄인다 |
| `note` | `label`, `body` | 작은 메모 상자. 보통 `pin: "bottom"` |
| `text` | `text`, `size`, `bold`, `color`, `alignment` | 자유 텍스트 한 줄·문단 |
| `table` | `columns[]`, `rows[][]`, `widths[]`, `bold_first_column`, `size` | 헤더 행이 있는 표. 행 높이는 가장 긴 셀에 맞춘다 |
| `mapping` | `left[]`, `right[]`, `links[[l, r]]`, `gutter`, `left_fill`, `right_fill` | 좌우 칩 두 열을 화살표로 잇는 대응 관계. `links` 없으면 같은 행끼리 |
| `hierarchy` | `root`, `children[]`(문자열 또는 `{label, children[]}`) | 루트 → 자식 가로 배치 → 손자 세로 칩의 2~3단 계층 |
| `primitives` | `primitives[]`, `origin: "flow"\|"slot"` | 골격에 없는 도식 하나를 슬롯 안에서 직접 그린다. 좌표는 본문 아래 현재 위치(`flow`) 또는 슬롯 좌상단(`slot`) 기준 상대값. 이름에 블록 접두어가 붙고 연결선은 같은 요소 안 이름이나 다른 블록 ID를 가리킨다 |

## 관계에 맞는 요소를 고르는 기준

골격과 요소는 배치의 하한선이지 내용을 끼워 맞추는 틀이 아니다. 블록의 관계가 아래 표의 어느 요소에도 맞지 않으면 칩으로 대체하지 말고 `primitives`로 그리거나, 장표 전체가 골격과 다르면 `shape_plan`을 직접 쓴다.

| 블록이 말하는 관계 | 쓰는 요소 | 칩으로 대체하면 생기는 왜곡 |
| --- | --- | --- |
| 서로 독립인 병렬 항목 3~4개 | `chips` | 없음 |
| 순서·순환 (A 다음 B, 다시 A) | `loop`, `steps` | 순서가 사라진다 |
| 항목 ↔ 대응 (요구와 구현, 문제와 해결) | `mapping` | 무엇이 무엇에 대응하는지 사라진다 |
| 행×열 비교 (단계별 기준, 항목별 담당) | `table` | 두 축 중 하나가 사라진다 |
| 상위 → 하위 분해 | `hierarchy` | 계층이 평평해진다 |
| 조건 분기 | `decision` | 분기 조건이 사라진다 |
| 수치 대비·지표 | `gauges`, `metric` | 수치가 본문 속에 묻힌다 |
| 위 어디에도 없는 도식 (아키텍처, N:M 연결, 시간 축) | `primitives` 또는 직접 `shape_plan` | 억지 매핑 |

`compose-shape-plan.mjs`는 블록별로 어떤 슬롯에 어떤 요소를 몇 개 썼는지 `blocks` 요약으로 출력하고, 검수 보고서의 `composition_summary`에도 남긴다. 와이어프레임 승인 때 관계를 표현해야 할 블록이 `chips`나 `headline+body only`로 끝났는지 이 요약에서 먼저 본다.

연결선 `from`/`to`에는 블록 ID(표면 도형으로 풀림) 또는 요소 도형 이름(`<block>-step-1-2`, `<block>-loop-1-3`, `<block>-chip-1-2` 등)을 쓴다.

## 골격을 고른 뒤 할 일

1. 블록마다 표면 도형 1개, 굵은 헤드라인 텍스트 1개, 본문 텍스트 1개를 슬롯 안에 둔다. 표면 안쪽 여백은 16~24px이다.
2. 블록 내용에 병렬 항목이 셋 이상이면 칩(둥근 사각형 11~12pt 굵게)이나 원 노드로 바꾸고 연결선으로 잇는다. 칩은 본문 아래에 둔다.
3. 슬롯 사이 간격은 20~30px로 유지한다. 연결선을 위해 60px 넘게 비우지 않는다. 연결선은 도형 사이를 지나가면 된다.
4. `estimateTextFit`가 계산하는 줄 수를 넘기지 않도록 문장을 줄이거나 상자를 키운다. 글자를 10~11pt로 줄여 맞추지 않는다.
5. 강조 대비를 준다. 한 장에 채운 진한 도형(primary·navy)은 하나 또는 둘이고, 나머지는 pale·white 표면에 line 테두리다.
6. 인접 장표와 같은 골격을 쓰더라도 슬롯 비율·허브 도형·칩 배치가 달라지면 구조 지문이 달라진다. 단, 세 장 연속으로 같은 골격을 쓰지 않는다.
