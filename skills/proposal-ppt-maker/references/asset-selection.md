# 제안서 자산 선택 및 재구성 규칙

## 1. 기본 정의

카탈로그 자산은 완성 슬라이드가 아니라 재사용 가능한 **시각 구조 모듈**이다. 원본 업무 주제, 원본 슬라이드 방향, 원본 비율은 최종 사용 범위를 제한하지 않는다.

`aspect_ratio`, `source_region`, 원본 슬라이드 크기는 추출 당시 형상 정보일 뿐이다. 별도 제한이 없다면 모든 자산을 `landscape`와 `portrait` 양쪽 후보로 본다.

## 2. 사용 모드

- `semantic`: 자산의 관계와 단계가 제안 내용과 직접 일치한다.
- `structural`: chain, split, hierarchy, wheel, lane 등 배치 구조를 재라벨링해 사용한다.
- `decorative`: 주제가 달라도 시각적 리듬, 강조, 초점 형성에 사용한다.

정확한 주제 자산이 없다는 이유만으로 폴백하지 않는다. 구조와 미감이 좋으면 `structural` 또는 `decorative`로 사용할 수 있다. 다만 원본의 숫자, 화살표, 인과관계가 근거 없는 사실처럼 보이지 않도록 재구성한다.

## 3. 내용 도식 우선

자산을 불릿 목록 옆에 장식처럼 붙이지 않는다. 세 개 이상의 병렬 불릿, 단계, 통제항목, 대안이 있으면 다음 구조에 직접 넣을 수 있는지 먼저 검토한다.

- 반복 항목: chain, repeated nodes, numbered flow
- 순환·통제: wheel, hub-spoke, feedback loop
- 대응 관계: mapping, matrix, two-column comparison
- 생애주기: lifecycle, roadmap, swimlane
- 구성 관계: architecture, hierarchy, system flow

긴 원문 불릿은 청사진에 보존하고, 노드에는 근거를 유지한 축약형 `content.diagram_labels`를 사용한다.

## 4. 방향 적응 순서

다음 순서로 검토한다.

1. 비례 조정
2. 텍스트 축약과 재라벨링
3. 반복 구조 재배치
4. 가로·세로 흐름 전환
5. 모듈 분할
6. 읽기 방향이 자연스러운 경우 회전
7. 더 단순한 카탈로그 구조로 교체
8. 네이티브 폴백

`원본이 가로형이고 대상이 세로형이다`는 폴백 사유가 아니다.

## 5. 최종 구현 계약

카탈로그 SVG는 디자인과 구조를 이해하기 위한 레퍼런스로만 사용한다. 최종 PPTX에서는 선택한 구조를 다음 요소로 다시 만든다.

- 개별 PowerPoint 원·사각형·선·연결선
- 개별 편집 가능한 텍스트
- 필요할 경우 독립적인 아이콘 도형

다음 방식은 금지한다.

- 화면 캡처 또는 스크린샷 붙여넣기
- PNG/JPG로 래스터화한 자산 삽입
- 원본 SVG 파일 직접 삽입
- SVG를 변환한 뒤 그룹 해제하도록 사용자에게 요구
- 여러 도형을 하나의 이미지나 편집 불가능한 그룹 그림으로 전달

최종 `render_mode`는 `native_powerpoint_shapes`여야 한다. 최종 슬라이드에는 사용자가 명시적으로 요청한 사진·로고 외에 `p:pic`, `ppt/media/*`가 없어야 한다.

네이티브 PowerPoint 도형끼리의 논리적 그룹화(`p:grpSp`)는 허용하며 편집 편의상 권장할 수 있다. 단, 다음 조건을 모두 만족해야 한다.

- 그룹의 모든 시각 요소가 네이티브 도형·연결선·텍스트다.
- 그룹 내부에 `p:pic`, SVG, 래스터 이미지, 미디어 관계가 없다.
- 그룹 해제 후 각 도형과 텍스트가 독립적으로 편집된다.
- 한 장의 그림을 도형 그룹처럼 위장하지 않는다.
- 의미 모듈 단위로 그룹화하고 슬라이드 전체를 하나의 거대 그룹으로 묶지 않는다.

## 6. 적합성 검사

재구성한 자산은 다음을 모두 만족해야 한다.

- 관계와 읽기 순서가 자연스럽다.
- 노드 수와 실제 콘텐츠 수가 일치한다.
- 최종 크기에서 모든 라벨을 읽을 수 있다.
- 원본 업무 주제와 제작 메모가 노출되지 않는다.
- 도형과 문구를 사용자가 개별 선택·수정할 수 있다.
- 승인된 방향과 여백을 벗어나지 않는다.
- PowerPoint 편집 화면과 내보낸 PNG에서 동일하게 보인다.

## 7. 복잡한 아키텍처

복잡한 아키텍처가 현재 지원하는 네이티브 도형으로 읽기 쉽게 재구성되지 않으면 다음 중 하나를 선택한다.

1. 더 단순한 구조 모듈로 대체한다.
2. 와이어프레임에 `architecture_required`와 `상세 아키텍처 필요`를 표시한다.

읽을 수 없는 작은 아키텍처를 최종 장표에 넣지 않는다. `상세 아키텍처 필요`는 제작 단계 표식이며 최종 청중용 문구가 아니다.

## 8. 매핑 기록

선택 자산마다 다음을 기록한다.

- `asset_id`
- `usage_mode`
- 어떤 구조를 차용했는지
- 방향 적응과 재배치 방법
- `render_mode: native_powerpoint_shapes`
- `renderer_key`: 실제 네이티브 토폴로지 렌더러

폴백 시에는 검토한 `asset_id`, 시도한 적응, 남은 가독성 문제, 더 단순한 구조가 필요한 이유를 기록한다.

## 9. 적용 상태와 fail-closed

`selected`, `loaded`, `applied`, `fidelity_passed`를 구분한다. SVG 파일을 읽고 해시를 계산한 것만으로 `applied` 또는 `used`라고 기록하지 않는다. 선택한 에셋의 필수 모티프가 최종 네이티브 도형 이름과 연결 구조에 존재할 때만 `fidelity_passed`로 기록한다.

지원되는 `renderer_key`가 없으면 generic card grid로 조용히 대체하지 않는다. `no_suitable_asset`으로 되돌려 사용자에게 알리거나 렌더링을 중단한다. 서로 다른 에셋을 선택했는데 동일한 구조 지문이 생성되면 검증 실패다.
