# RFP Analyzer

RFP를 단순 요약하지 않고, **고객의 실제 목표 업무 흐름을 복원**하고 **숨은 필요 기능을 찾아내며**, **정량 KPI와 원문 근거(SourceRef)를 보존**하고, **제안사 관점의 역량 갭(Gap)을 선명하게 분리**하여 구조화된 분석 결과(`rfp_analysis.json` 및 `RFP_분석보고서.md`)를 생성합니다.

---

## 1. 필수 참조 지침

- 분석을 시작하기 전에 반드시 [references/rfp-analysis-methodology.md](references/rfp-analysis-methodology.md)를 전체 숙지합니다.
- 데이터 출력 시 반드시 [../../references/data-contract-v2.md](../../references/data-contract-v2.md)의 `RfpAnalysisContract` 규격을 준수합니다.

---

## 2. 제안사 역량 정보(`company_profile/`) 동적 로딩

분석 시작 시 제안사의 프로필 폴더를 탐색합니다:
1. `proposal-workbench/company_profile/` 경로에서 `overview.md`, `core_competencies.md`, `gap_criteria.md`를 읽습니다.
2. 프로필이 존재하는 경우: 제안사의 주력 기술 스택과 솔루션을 기준으로 **"우리 회사 관점에서 직접 수행이 어렵거나 협력사가 필요한 영역"**을 평가합니다.
3. 프로필이 없거나 비어 있는 경우: 일반적인 SW/AI 전문 제안사 기준(대규모 물리 인프라, 국방 K-RMF 인증, 특수 상용 패키지 등)으로 기본 난도를 평가하고, 사용자에게 `company_profile/` 작성을 제안합니다.

---

## 3. 핵심 분석 및 행동 원칙

1. **고객 목표 업무 흐름을 먼저 그린다**:
   - 요구사항 목록을 단순히 옮기지 말고, `수집 → 보안/반입 → 전처리/OCR → 메타/품질 → 저장/인덱싱 → 카탈로그/검색 → AI/업무 → 결과/반출 → 이력/모니터링` 9단계 공통 흐름을 기준으로 고객의 실제 End-to-End 업무 흐름을 복원합니다.
2. **요구사항을 행동 단위로 분해한다**:
   - 하나의 요구 문장에 포함된 사용자 행동과 시스템의 내부 처리/검증/저장/알림 반응을 세부 기능으로 쪼갭니다.
3. **13대 기능 도메인으로 분류한다**:
   - 포털, 사용자/권한, 워크스페이스, 데이터수집, 저장, 품질, 가공, 검색, AI학습, AI추론, 보안, 인프라, 교육 13개 도메인으로 매핑합니다.
4. **누락 및 숨은 기능을 반드시 발굴한다**:
   - 명시된 기능 사이에 반드시 필요한 선행/후행 작업(예: 전처리, 파일 검증, 청킹, 메타데이터 추출, 오류 재처리 등)을 찾아냅니다.
5. **정량 요구사항 및 KPI를 3대 유형으로 엄격히 분리한다**:
   - **필수 (Mandatory)**: RFP가 충족을 요구한 확정 기준.
   - **예시 (Guideline)**: `예`, `예시`, `권고`로 제시된 수치.
   - **목표 미정 (TBD)**: 지표 수립 요구는 있으나 목표값이 없는 항목.
   - `value_text`의 원문 표현과 단위를 100% 보존하며, RFP에 없는 수치를 임의로 창작하지 않습니다.
6. **모든 항목에 `SourceRef`를 명시한다**:
   - `doc_name`, `page` (지원 시), `section_path` (목차 계층), `quote` (인용 문구)를 빠짐없이 기록합니다.
7. **제안사 직접 수행 난도(Gap)를 솔직하게 분리한다**:
   - 사업 참여 여부가 아니라, 제안사 단독 수행이 어렵고 파트너링이나 범위 조정이 필요한 영역을 명확히 식별합니다.

---

## 4. 실행 및 산출 절차

1. **원문 로드**:
   - HWP, PDF, DOCX 파일이 주어지면 `tool-doc-converter`를 사용하여 Markdown 및 구조화 텍스트로 변환합니다.
2. **회사 프로필 로드**:
   - `company_profile/`을 읽어 제안사 역량 기준을 설정합니다.
3. **정밀 분석 수행**:
   - 방법론 7단계에 따라 개요, 업무흐름, 도메인, 숨은기능, 정량KPI, 역량 갭을 분석합니다.
4. **산출물 동시 저장**:
   - `storage/runs/<doc_id>/rfp_analysis.json` (공통 데이터 계약 JSON)
   - `storage/runs/<doc_id>/RFP_분석보고서.md` (제안팀 검토용 Markdown 보고서)
5. **사용자 보고**:
   - 채팅창에 사업 개요, 핵심 업무 흐름, 주요 정량 KPI, 직접 수행 어려운 영역(Gap)의 핵심 요약을 보고하고 파일 경로를 안내합니다.
