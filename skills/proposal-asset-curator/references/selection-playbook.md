# 자산 후보 선별 플레이북

## 판정 순서

1. 현재 OOXML element의 직접 태그가 `p:grpSp`인지 확인한다. 하위 XML에 연결선이 있다는 이유로 그룹을 connector로 판정하지 않는다.
2. PowerPoint 그룹, 큰 배경·테두리 shell, 동일 정렬·간격의 제목/본문/배지, connector component, 가까운 공간 클러스터 순서로 블록을 나눈다.
3. 제목·페이지 번호·각주·SAMPLE 스탬프·사용 가이드·슬라이드 밖 도형·0 크기 도형·얇은 반복 장식 PNG는 후보에서 제외한다.
4. 블록 외형과 내부 도식을 따로 재사용할 수 있으면 분리한다. 프로세스와 표가 한 장표에 같이 있으면 각각 후보로 둔다.
5. 후보는 `selected`, `deferred`, `rejected` 중 하나만 갖는다. 숫자 점수는 만들지 않는다.

## 정성 판정

- `selected`: 네이티브 도형·연결 관계·읽기 순서가 남고, 블록 로컬 좌표와 `wide`·`compact`·`tall` 배치로 재배치할 수 있다.
- `deferred`: 표·Gantt·고정형 아키텍처처럼 구조는 유용하지만 다른 크기에서 의미가 깨지거나 추가 분리가 필요하다.
- `rejected`: 차트/SmartArt/OLE가 핵심이거나 화면 캡처·사진이 구조 자체라 네이티브 편집을 보장할 수 없다.

이유는 1~2문장으로 쓰고 `cleanup_actions`에는 실제로 할 일만 적는다. 원본 문구를 이유에 복사하지 말고 “원문 라벨을 의미 슬롯으로 치환”처럼 표현한다.

## 이미지와 플레이스홀더

작은 raster icon은 핵심 shell·관계를 보존할 수 있으면 `icon_slot`으로 바꾼다. 사진 영역은 `media_slot`으로 바꾸고 프레임만 유지한다. 사진 자체를 영구 보존하는 `photo_asset`은 별도 후보·라이선스 승인이 필요하다. 사진이 핵심인 블록은 억지로 네이티브 도식으로 만들지 않는다.

## 대표 후보와 증거

정규화된 경계·도형 종류·연결 topology·텍스트 슬롯 서명이 같은 후보는 첫 번째 깨끗한 후보를 대표로 두고 후속 후보의 `duplicate_of`에 기록한다. 회사명·원본 파일명·source path는 후보 로컬 JSON에만 남고 승인 자산에는 남기지 않는다.

렌더러가 비정상 종료했어도 예상 PNG/레이아웃 파일과 직접 OOXML 추출이 모두 있으면 evidence는 `warning`이다. 예상 파일이 하나라도 없거나 직접 추출 수가 모자라면 `partial`이다. 둘을 `complete`로 뭉개지 않는다.

## 실제 검토에서 자주 생기는 실패

- `p:grpSp` 안에 connector가 있어서 그룹 전체가 선 하나로 분류되는 문제: 직접 태그만 본다.
- 미리캔버스 export가 도식을 한 장의 PNG로 만들거나 모든 요소를 사진으로 넣는 문제: 원본 네이티브 PPTX/POTX를 요청하고 사진은 별도 분리한다.
- 큰 빈 패널과 짧은 문구만 남겨 “고밀도”라고 부르는 문제: 노드 라벨은 줄여도 세부 설명·통제·검증·예외는 편집 가능한 텍스트로 보존한다.
- 복잡한 아키텍처·표를 억지로 고정 비율로 줄이는 문제: 구조는 `deferred`로 두고 설명 우선 또는 시리즈 분할을 검토한다.
- 제목·각주·SAMPLE을 템플릿에 복사하는 문제: 콘텐츠 슬롯으로 치환하고 영구 카탈로그 바이트를 검사한다.
